Usage patterns

Use the managed solution assets that match the target host: Power Pages web files, Model-Driven App JavaScript, or the Canvas PCF control.

Power Pages

  • Create site-specific web files from dodbl_bannercore and dodbl_dodconsentbanner.
  • Create the web template using dodbl_webtemplatesource.
  • Do not package a website record; website IDs are environment-specific.

Model-Driven Apps

  • Add dodbl_dodbanner as a form library.
  • Register DoDBannerLibrary.DodBanner.onFormLoad on form OnLoad.
  • Use environment variables for banner type, placement, consent text, and enablement.

Canvas Apps and custom pages

  • Add the DoDBannerLibrary.DodBannerControl PCF control.
  • Bind bannerEnabled and set bannerType, showConsent, consentExpiryDays, and consentText.
  • Republish apps after updating the PCF bundle.

Consent modal markup

The consent modal elements are referenced by exact ID and class names. Do not rename them without updating all corresponding JavaScript and PCF code.

<div id="cookieConsent">
  <a id="closeCookieConsent">&#x2715;</a>
  <p>Your AO-approved system-use notification text here.</p>
  <a class="cookieConsentOK">I Acknowledge</a>
</div>
<div class="consentBackground"></div>

Consent wording: Replace placeholder text with AO-approved system-use notification language for the adopting organization. The library surfaces the text; it does not establish the authorization boundary.

Classification marks

The CSS-only path uses the case-sensitive data-classification attribute. Use the canonical uppercase values shown here.

<div class="classification-banner" data-classification="CUI">
  <!-- page content -->
</div>

<div class="classification-banner-bot" data-classification="SECRET">
  <!-- page content -->
</div>

<div class="classification-banner"
     data-classification="CUI"
     data-banner-content="CONTROLLED UNCLASSIFIED INFORMATION">
</div>

Environment variables

These dodbl_ variables control the Model-Driven App JavaScript path. Canvas PCF uses its component properties instead of reading environment variables directly.

Schema nameTypeDefaultDescription
Administration → Banner Configuration in the management app (dodbl_banner-config) lets an administrator change dodbl_BannerEnabled, dodbl_BannerType, dodbl_BannerPosition, and dodbl_ConsentExpiryDays without the maker portal or a redeploy. It requires the DoD Banner - Config Admin or System Administrator role, and changes apply on each user’s next page load.
dodbl_BannerEnabledBooleantrueSet to false to disable banners environment-wide for the MDA path.
dodbl_BannerTypeStringemptyClassification bar to render: CUI, UNCLASSIFIED, CONFIDENTIAL, SECRET, or TOP SECRET. Empty means no bar.
dodbl_ConsentExpiryDaysNumber30Days before the consent cookie expires.
dodbl_DoDConsentTextStringemptyAO-approved consent text override. Empty uses the built-in default text for the relevant surface.
dodbl_ShowConsentBannerBooleanfalseLegacy form-script consent notification toggle; the v1.3 management app consent gate uses the custom launch page.
dodbl_BannerPositionStringBottomClassification bar placement: Bottom, Top, or Both. Top placement shifts the MDA nav header down 28 px.

Known limitations

These notes are intentionally explicit so adopters can plan testing and governance reviews.

Canvas per-session consent limitation

In v1.3.0, consent acknowledgement does not reliably persist across sessions when DodBannerControl runs inside a Canvas App. The modal still functions per session, but cross-session persistence is limited by the Power Apps code-component sandbox. Persistent Canvas consent is tracked in issue #21; v1.4.0 consent-audit work is in progress.

Client-side acknowledgement is not enforcement

Client-side consent can be bypassed through deep links, direct API/OData access, disabled JavaScript, or browser developer tools. Use platform-level controls if enforced acknowledgement is required.

MDA shell bar supportability

The MDA classification bar uses window.top.document because no supported UCI API exists for a persistent outer-shell classification bar. This is documented as an accepted supportability risk in project ADRs.
