1. Overview and scope

The DoD Banner Library is a managed Power Platform solution for reusable classification bars and optional system-use notification experiences.

Model-driven apps

Launch-page and form-script paths for shell classification bars and consent acknowledgement.

Canvas apps and custom pages

PCF control support for self-contained classification and consent UI.

Power Pages

Portable web resources and template source without packaging environment-specific website records.

Current public product line: v1.5.0.

Key constraints: publisher prefix dodbl_; no external CDN calls, fonts, scripts, or jQuery; managed solution distribution; environment-variable driven Model-Driven App behavior; and client-side consent UX as supplementary hardening, not a hard authorization boundary.

3. Environment variables

The Model-Driven App banner path is configured with these six public banner settings.

Schema nameTypeDefaultDescription
dodbl_BannerEnabledYes/NoYesMaster switch. No suppresses banners for the MDA path.
dodbl_BannerTypeStringemptyClassification value: U/UNCLASSIFIED, CUI, CONFIDENTIAL, SECRET, TOP SECRET, or legacy DoD alias. Empty means no classification bar.
dodbl_BannerPositionStringBottomClassification bar placement: Top, Bottom, or Both.
dodbl_ConsentExpiryDaysInteger30Days before the dodbl_Accepted consent cookie expires. 0 re-prompts each browser session.
dodbl_BannerColorStringemptyOptional hex color override such as #5cb85c. Empty uses the automatic classification color. Invalid values are ignored by runtime code.
dodbl_BannerVersionString1.5.0.0Running-version stamp shown in the app. Release owners keep this in sync with Solution.xml.

4. Admin configuration screen

dodbl_banner-config provides an in-app admin screen for authorized users. It is intended for holders of DoD Banner - Config Admin or System Administrator.

Edits values

Edits Environment Variable Value records, not definitions. Saves show modifiedby and modifiedon attribution in the UI.

Configuration scope

Lets admins change banner enablement, type, position, consent expiry, and optional color override without redeploying the solution.

Runtime aids

Displays dodbl_BannerVersion read-only, refreshes the visible shell bar when available, and includes Reset My Consent to clear the current user's cookie.

Dataverse privileges remain the enforcement boundary. Client-side role checks are usability gates, not a substitute for Dataverse security.

5. Consent and audit behavior

The Model-Driven App launch page writes a dodbl_consentrecord when a user acknowledges the system-use notification.

Record fields

The record captures user, banner type, acknowledged-on timestamp, expiry timestamp, and consent text snapshot.

Consent audit roles

DoD Banner - Consent Write supports creation. DoD Banner - Consent Audit Reader provides read-only review access.

Canvas limitation

Canvas-hosted PCF consent is useful for in-app UX but does not provide this supported Dataverse audit-write path. Use the Model-Driven App launch page when a persisted audit record is required.

7. Classification bar implementation notes

Implementation details that integrators should understand before review or rollout.

For Model-Driven Apps, the shell classification bar uses window.top.document so it appears in the visible UCI shell rather than only inside a form or web-resource iframe. This is limited to classification-bar DOM placement and uses cleanup markers (data-dodbl-bar) to avoid duplicate bars during navigation.

dodbl_BannerColor is validated with a hex-color allow-list (#RGB or #RRGGBB). Malformed values fall back to the classification-type default, preventing arbitrary CSS injection.

8. Import and verification checklist

Generic post-import checks for reviewers and makers.

Import and publish

Import the managed solution and publish all customizations.

Verify app navigation

Open the management app and confirm Home, Banner Configuration, Consent Records, Documentation, Release Notes, Web Template Source, and Canvas App Demo are available as expected.

Assign roles

Assign DoD Banner - Config Admin only to users authorized to change banner settings. Assign consent audit roles according to least-privilege review needs.

Check configuration

Open Banner Configuration and verify the current version, banner settings, and value attribution display.

Test acknowledgement

Test the launch page acknowledgement path and confirm a consent audit record is created where the user has required privileges.

Retest prompt

Use Reset My Consent to clear the current user's cookie and retest the prompt.
